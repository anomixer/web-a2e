# Main Emulator

> Core emulator power and reset controls.

## ⚠️ RULE 0 — Never move bytes through the LLM (read this first)

base64 blobs and file dumps burn the user's context and slow every turn. A
bypass tool that keeps the bytes server-side almost always exists. **Default to
the bypass.** Use base64 only when no bypass exists for that source — and when
you do, say so out loud (that's the cue to add a new bypass tool).

| You're about to… | base64 way — AVOID | bypass — USE |
| --- | --- | --- |
| put a sandbox/host file in memory | `load_file` → `directLoadBinaryAt` | **`directLoadFileAt`** `{ address, path }` |
| put a disk-image file in memory | `getDiskFileContent` → `directLoadBinaryAt` | **`directLoadFileAt`** `{ address, filename, drive }` |
| load `.asm` source to assemble | `load_file` → `asmSet` | **`asmLoadFile`** `{ path }` |
| copy a memory block | `directSaveBinaryRangeTo` → `directLoadBinaryAt` | **`directMemoryCopy`** `{ src, dst, length }` |
| blank/fill a memory block | zero-blob → `directLoadBinaryAt` | **`directMemoryFill`** `{ address, length, value }` |
| save memory to a file | `directSaveBinaryRangeTo` → write | **`save_to`** `{ from:"memory-range" }` |
| save editor/screen to a file | `asmGet`/`capture*` → write | **`save_to`** `{ from:"asm-editor" \| "basic-editor" \| "screen" }` |
| look at the screen | `captureScreenshot` (base64) | **`get_screenshot`** (MCP) or **`save_to`** `{ from:"screen" }` |
| run a routine, then verify RAM | execute → BASIC clobbers pages | `directExecuteAssemblyAt` `{ returnTo:"halt" }` (CPU spins, RAM frozen) |

This rule holds across context compaction — do not silently fall back to base64.

## Tool Operations

**Power control:**
```
emma_command({ command: "emulatorPower", params: { action: "on" } })
emma_command({ command: "emulatorPower", params: { action: "off" } })
emma_command({ command: "emulatorPower", params: { action: "toggle" } })
```
Control emulator power state. Action can be "on", "off", or "toggle" (default).

**Ctrl-Reset:**
```
emma_command({ command: "emulatorCtrlReset", params: {} })
```
Warm reset - restarts the emulator without clearing memory.

**Reboot:**
```
emma_command({ command: "emulatorReboot", params: {} })
```
Cold reset - full reboot that clears all memory.

## Memory Operations

### Preferred (no base64 in context)

**Load a file straight into memory — `directLoadFileAt`:**
```
emma_command({ command: "directLoadFileAt", params: { address: "$2000", path: "[t]/bin/pic.bin" } })
emma_command({ command: "directLoadFileAt", params: { address: "$6000", filename: "HGR.ART", drive: 0 } })
emma_command({ command: "directLoadFileAt", params: { address: "$2000", filename: "PIC", drive: 0, offset: "$04" } })
```
Loads a binary directly into emulator memory with the bytes kept server-side — **never base64 through the LLM**. Pick ONE source:
- `path` — a sandbox/host file (read via the MCP `load_file` tool, decoded in the browser).
- `filename` (+ optional `drive`, default 0) — a file in the DOS 3.3 / ProDOS disk image currently mounted in that drive.

Optional `offset`/`length` (hex or decimal) slice the file before writing (e.g. skip a 4-byte BSAVE header). This replaces `load_file`/`getDiskFileContent` + `directLoadBinaryAt`.

**Copy a memory block — `directMemoryCopy`:**
```
emma_command({ command: "directMemoryCopy", params: { src: "$2000", dst: "$4000", length: "$2000" } })
```
Copies `length` bytes from `src` to `dst` entirely Apple-side. The source is buffered first, so overlapping ranges are safe. Reads follow the current RAMRD bank, writes the current RAMWRT bank — set soft switches first if you need a specific main/aux bank. (e.g. promote HGR page 1 → page 2 without a host round-trip.)

**Fill/blank a memory block — `directMemoryFill`:**
```
emma_command({ command: "directMemoryFill", params: { address: "$2000", length: "$2000", value: 0 } })
```
Writes the constant byte `value` (default 0) across the range. Use this to blank a graphics page instead of loading a zero-filled base64 blob.

**Save memory range to a file (single step, no base64):**
```
save_to({ from: "memory-range", address: "$0800", length: "$0400", whereTo: "[files]/output.bin" })
```

### Fallback (base64 passes through the LLM — avoid unless no bypass fits)

**Load binary data to memory — `directLoadBinaryAt`:**
```
emma_command({ command: "directLoadBinaryAt", params: { address: "$2000", contentBase64: "<base64 data>" } })
```
⚠️ base64 in context. Prefer `directLoadFileAt`. Only use this when the bytes were generated in-conversation and exist nowhere on disk.

**Save memory range to base64 — `directSaveBinaryRangeTo`:**
```
emma_command({ command: "directSaveBinaryRangeTo", params: { address: "$2000", length: "$0100" } })
```
⚠️ base64 in context. Prefer `save_to { from:"memory-range" }` to capture to a file. Only use this for a tiny readback you must inspect inline (a few bytes).

## Screen Capture

**View screenshot in LLM context (use MCP tool — not emma_command):**
```
get_screenshot()
```
Captures the current screen and returns it as a viewable image in the LLM context. Use this to inspect the screen visually.

**Capture screenshot as PNG (app tool — returns base64):**
```
emma_command({ command: "captureScreenshot", params: {} })
```
Returns base64-encoded PNG. Prefer `save_to` or `get_screenshot` over this to avoid base64 in the conversation.

Returns:
```
{
  success: true,
  imageBase64: "data:image/png;base64,iVBORw0KG...",
  width: 560,
  height: 384,
  message: "Screen captured as 560x384 PNG"
}
```

**Read text from screen:**
```
emma_command({ command: "captureScreenText", params: {} })
emma_command({ command: "captureScreenText", params: { startRow: 0, startCol: 0, endRow: 23, endCol: 79 } })
```
Reads text content from the Apple //e screen. All parameters are optional and default to full screen (24 rows x 80 columns). Useful for reading program output, catalog listings, or error messages.

Parameters:
- `startRow`: Starting row (0-23, default 0)
- `startCol`: Starting column (0-79, default 0)
- `endRow`: Ending row (0-23, default 23)
- `endCol`: Ending column (0-79, default 79)

Returns:
```
{
  success: true,
  text: "CATALOG\n\nDISK VOLUME 254\n\n A 002 HELLO\n...",
  startRow: 0,
  startCol: 0,
  endRow: 23,
  endCol: 79,
  message: "Screen text captured from (0,0) to (23,79)"
}
```

## Keyboard Input

**Type text and special keys:**
```
emma_command({ command: "typeKeyboard", params: { text: "CATALOG\n" } })
emma_command({ command: "typeKeyboard", params: { text: "10 PRINT 123{enter}RUN{enter}" } })
```
Types text into the emulator exactly as if entered at the keyboard, through the accelerated paste queue. Plain text types literally; newlines (`\n`) act as Return.

Special keys use `{token}` syntax:
- Arrows: `{left}` `{right}` `{up}` `{down}`
- Editing/control: `{esc}` `{enter}`/`{return}`/`{cr}` `{tab}` `{del}` `{backspace}` `{space}`
- Ctrl combos: `{ctrl-c}`, `{ctrl+c}`, or `{^c}` (any letter)
- Raw code by value: `{chr:4}` (decimal) or `{chr:$1b}` / `{chr:0x1b}` (hex) — equals `CHR$(N)`, for control codes and bytes a key name doesn't cover
- Literal brace: `{{` produces a single `{`

Parameters:
- `text`: String to type. Required. May contain `{token}` special keys.

Returns:
```
{ success: true, length: 8, message: "Typed 8 characters" }
```

Notes:
- `CHR$(4)` (Ctrl-D, the DOS/ProDOS command char) = `{chr:4}` or `{ctrl-d}`. To issue a DOS command *from a running program* you still type the literal BASIC line, e.g. `PRINT CHR$(4);"PR#1"` (all printable, no tokens needed).
- Token parsing is on for this tool; ordinary clipboard paste still treats braces literally.

## Workflow Examples

**Loading a binary file into memory (single step, no base64):**
```
emma_command({ command: "directLoadFileAt", params: { address: "$2000", path: "[t]/program.bin" } })
```

**Promote HGR page 1 → page 2 and blank page 1 (no host round-trip):**
```
emma_command({ command: "directMemoryCopy", params: { src: "$2000", dst: "$4000", length: "$2000" } })
emma_command({ command: "directMemoryFill", params: { address: "$2000", length: "$2000", value: 0 } })
```

**Run a routine then verify RAM without BASIC clobbering it:**
```
emma_command({ command: "directExecuteAssemblyAt", params: { addr: "$6000", returnTo: "halt" } })
```
The CPU spins in a JMP-self pad after the routine's RTS, so `$2000`/`$4000` (or any RAM) stay frozen for screenshot + readback.

**Saving memory range to local filesystem (single step, no base64 in context):**
```
save_to({ from: "memory-range", address: "$0800", length: "$0400", whereTo: "[files]/output.bin" })
```

**Capturing screenshot to local filesystem (single step, no base64 in context):**
```
save_to({ from: "screen", whereTo: "[t]/screenshot.png" })
```

**Viewing screenshot in LLM context:**
```
get_screenshot()
```

**Reading program output from screen:**
1. Capture text: `captureScreenText({ startRow: 5, startCol: 0, endRow: 15, endCol: 79 })`
2. Process the text in `result.text`

## Multi-Emulator

Multiple Apple //e browser tabs can connect to the MCP server simultaneously. Each tab is assigned a unique name (e.g. "Bingo", "Wozulator").

**See what's connected:**
```
list_connections()
```
Returns all connected emulators with name, state, and which is the default. Call this at the start of a multi-emulator session.

**Set the default:**
```
set_default_emulator({ name: "Bingo" })
```
All subsequent tool calls route to Bingo unless overridden. Do this immediately after the user picks an emulator — don't ask again on each command.

**Target a specific emulator:**
```
emma_command({ command: "captureScreenText", params: {}, emulator: "Bingo" })
get_screenshot({ emulator: "Wozulator" })
save_to({ from: "screen", whereTo: "[t]/shot.png", emulator: "Bingo" })
```

**Broadcast to all:**
```
emma_command({ command: "emulatorReboot", params: {}, emulator: "all" })
```

**Routing rules (when `emulator` param is omitted):**
- 1 connected → use it automatically
- Multiple connected → use the one marked as default
- Multiple + no default → Claude picks and immediately calls `set_default_emulator`

**Emulator names:**
- Assigned from a name pool on connect; persisted in `sessionStorage` across server restarts
- Double-click the name label on the sparkle button (browser UI) to rename inline
- Valid names: Unicode letters, hyphens, underscores — no numbers or spaces

**Broken emulators:**
- Routing is blocked to emulators with a broken connection
- Warn the user and wait for them to reconnect or pick a different emulator
